# Search Scout

Telegram-бот для личного использования. Он ищет в поисковом спросе гипотезы для
небольших цифровых продуктов: микросервисов, Telegram-ботов, SaaS и инструментов
автоматизации.

Бот каждый день:

1. берёт стартовые фразы по 18 тематикам (`config/topics.toml`) и расширяет их;
2. получает связанные запросы и частотность из Яндекс Wordstat (или из CSV);
3. нормализует фразы, убирает дубликаты и нерелевантное;
4. копит историю и считает динамику спроса (рост, всплески, сезонность);
5. оценивает каждую фразу по прозрачным правилам (0–100) с объяснением;
6. присылает в Telegram отчёт: лучшие возможности и список наблюдения.

**Главный принцип: бот не выдумывает данные.** Если частотности нет, он пишет «нет
данных». Если нет истории, он пишет «недостаточно истории», а не рисует рост.
Конкуренция без данных о конкурентах помечается как «не исследована». Рейтинг —
эвристика для сортировки гипотез, а не прогноз прибыли.

## Как это устроено

```
search-scout/
├── app/
│   ├── __main__.py        командная строка: python -m app [bot|scan|import-csv|report|...]
│   ├── main.py            запуск Telegram-бота
│   ├── config.py          настройки из .env (секреты скрыты)
│   ├── context.py         сборка всех частей приложения
│   ├── topics.py          загрузка тематик и правил расширения
│   ├── scheduler.py       ежедневный запуск и восстановление после перезапуска
│   ├── single_instance.py защита от второй копии бота
│   ├── logging_setup.py   логи с маскировкой токенов
│   ├── bot/
│   │   ├── access.py      пускает только разрешённые user ID
│   │   └── handlers.py    команды /start, /scan, /report ...
│   ├── sources/
│   │   ├── base.py        общий интерфейс источников
│   │   ├── http.py        лимит частоты, повторы, обработка 429/5xx
│   │   ├── csv_source.py  импорт CSV
│   │   └── wordstat.py    Яндекс Wordstat (Yandex Cloud Search API v2)
│   ├── services/
│   │   ├── normalizer.py  нормализация, дубликаты, группировка
│   │   ├── intent.py      коммерческое намерение и выраженность проблемы
│   │   ├── trend.py       динамика, всплески, сезонность
│   │   ├── scorer.py      итоговый рейтинг и отбор
│   │   ├── collector.py   конвейер сканирования
│   │   ├── ideas.py       гипотеза продукта и следующий шаг
│   │   ├── report.py      тексты отчётов и экспорт CSV
│   │   └── notifier.py    рассылка без повторов
│   └── storage/
│       ├── models.py      таблицы
│       ├── migrations.py  версии схемы базы
│       ├── database.py    подключение к SQLite
│       └── repository.py  все запросы к базе
├── config/topics.toml     тематики, стартовые фразы, модификаторы, стоп-слова
├── data/demo_keywords.csv СИНТЕТИЧЕСКИЕ тестовые данные для Demo-режима
├── tests/                 автотесты (pytest)
├── .env.example           шаблон настроек
├── pyproject.toml, requirements.txt, requirements-dev.txt
```

**Режимы.**
- **Demo/CSV** — работает без ключей. Данные берутся из CSV. По умолчанию это
  `data/demo_keywords.csv`: синтетический файл, помеченный как тестовый. Каждый отчёт
  в этом режиме начинается с плашки «🧪 ТЕСТОВЫЕ ДАННЫЕ».
- **Live** — реальные данные из Wordstat API. Тестовые данные в Live-отчёты
  не попадают никогда: в базе демо- и реальные фразы хранятся раздельно.

**База данных (SQLite)**, одна таблица на одну задачу:

| Таблица | Зачем |
|---|---|
| `topics` | тематики из `topics.toml` |
| `seed_queries` | стартовые фразы и фразы из расширения; когда опрашивались |
| `phrases` | уникальные фразы (исходная и нормализованная форма, группа, демо или нет) |
| `metric_snapshots` | частотность фразы за месяц или «последние 30 дней» по датам |
| `scan_runs` | журнал сканирований (статус, статистика, ошибки) |
| `scores` | история оценок: итог, компоненты, причины, использованные данные |
| `opportunities` | текущий статус фразы: `top` / `watch` (наблюдение) / `rejected` |
| `telegram_users` | пользователи бота и включён ли ежедневный отчёт |
| `notifications` | что и кому уже отправлено (защита от повторов) |

«Найденные возможности» и «список наблюдения» — это одна таблица `opportunities`
с разными статусами: так одна фраза не может оказаться в двух местах одновременно.

Время хранится в UTC. В отчётах оно переводится в ваш часовой пояс (`TIMEZONE`).
Схема базы версионируется (`app/storage/migrations.py`, версия лежит в
`PRAGMA user_version`). При обновлении схемы бот сам применит миграции и
перед этим сделает копию базы `*.bak`.

## 1. Установка Python

Нужен Python **3.12 или новее** (проверено на 3.12 и 3.13).

**Windows.** Скачайте установщик с <https://www.python.org/downloads/>. При установке
отметьте галочку **«Add python.exe to PATH»**. Проверка в PowerShell:

```powershell
py --version
```

**macOS.** Установите с python.org или через Homebrew (`brew install python@3.12`).
**Linux (Ubuntu/Debian):** `sudo apt install python3 python3-venv`.

```bash
python3 --version
```

## 2. Виртуальное окружение

Окружение — это отдельная папка с библиотеками проекта, чтобы они не мешали другим
программам. Перейдите в папку проекта (`search-scout`).

**Windows (PowerShell):**

```powershell
cd путь\к\search-scout
py -3.12 -m venv .venv
.venv\Scripts\Activate.ps1
```

Если PowerShell пишет, что выполнение скриптов запрещено, один раз выполните
`Set-ExecutionPolicy -Scope CurrentUser RemoteSigned`.

**macOS / Linux:**

```bash
cd путь/к/search-scout
python3 -m venv .venv
source .venv/bin/activate
```

После активации в начале строки терминала появится `(.venv)`. Активировать нужно
в каждом новом окне терминала.

## 3. Установка зависимостей

```bash
pip install -r requirements-dev.txt
```

`requirements.txt` содержит точные версии всех пакетов для работы бота, а
`requirements-dev.txt` добавляет к ним pytest и Ruff. На сервере достаточно
`pip install -r requirements.txt`.

## 4. Создание Telegram-бота через @BotFather

1. Откройте в Telegram [@BotFather](https://t.me/BotFather) и отправьте `/newbot`.
2. Введите имя (например, `My Search Scout`) и username, оканчивающийся на `bot`.
3. BotFather пришлёт **токен** вида `123456789:AA...`. Это пароль от бота: никому его
   не показывайте и не коммитьте в git.
4. Рекомендуется: `/setjoingroups` → **Disable**, чтобы бота нельзя было добавить в группы.

## 5. Как узнать свой Telegram user ID

Самый простой способ — спросить у самого бота. Запустите его с пустым
`ALLOWED_USER_IDS` и напишите ему что угодно. Бот ответит:
«Это приватный бот. Ваш Telegram ID: 123456789». Впишите этот номер в `.env`
и перезапустите бота.

Другой способ — написать боту [@userinfobot](https://t.me/userinfobot).

## 6. Настройка .env

Скопируйте шаблон.

Windows: `copy .env.example .env` · macOS/Linux: `cp .env.example .env`

Откройте `.env` в редакторе и заполните минимум:

```ini
TELEGRAM_BOT_TOKEN=123456789:AA...
ALLOWED_USER_IDS=123456789
```

Остальное можно не трогать: без ключей Wordstat бот работает в Demo-режиме.
Все параметры описаны в `.env.example`. Дополнительные параметры: веса рейтинга
`WEIGHT_TREND`, `WEIGHT_COMMERCIAL`, `WEIGHT_PROBLEM`, `WEIGHT_NOVELTY`, порог топа
`TOP_MIN_SCORE` (55), минимальный объём для динамики `MIN_MONTHLY_VOLUME` (50 в месяц),
`REPORT_MAX_ITEMS` (10).

`.env` уже внесён в `.gitignore` и не попадёт в репозиторий. То же касается базы
`data/*.sqlite3`: в ней хранятся ваши Telegram ID и история.

## 7. Запуск

```bash
python -m app
```

В логе появится `Бот @ваш_бот запущен`. Откройте бота в Telegram и отправьте `/start`,
затем `/scan` и `/report`.

Остановка — `Ctrl+C`. Бот можно перезапускать в любой момент: расписание
восстановится, отправленные отчёты не повторятся.

Те же действия без Telegram (удобно для проверки):

```bash
python -m app scan            # одно сканирование
python -m app report          # отчёт в терминал
python -m app export out.csv  # выгрузка всех результатов
python -m app --help          # все команды
```

Команды `scan` и `import-csv` в терминале не работают, пока запущен бот: это защита
от двух одновременных сканирований. Пока бот запущен, пользуйтесь `/scan` и
отправкой CSV в Telegram.

## 8. Тесты

```bash
pytest
ruff check app tests
ruff format --check app tests
```

Обычные тесты не обращаются к интернету и платным API. Все тестовые данные в них
синтетические. Отдельный тест настоящего Wordstat тратит 1–2 запроса квоты и
запускается только явно:

```bash
# macOS/Linux
SCOUT_LIVE_TESTS=1 pytest -m live
# Windows (PowerShell)
$env:SCOUT_LIVE_TESTS="1"; pytest -m live
```

## 9. Импорт CSV

Формат: первая строка — заголовок, разделитель `,` или `;`, кодировка UTF-8 или
Windows-1251. Строки, начинающиеся с `#`, — комментарии.

| Колонка | Обязательна | Значение |
|---|---|---|
| `phrase` | да | поисковая фраза |
| `count` | нет | частотность; **пусто = «нет данных»**, а не ноль |
| `period` | нет | `month` — за календарный месяц; `30d` — за 30 дней до `date` (по умолчанию) |
| `date` | нет | `2026-09-01`, `01.09.2026` или `2026-09`; по умолчанию сегодня |
| `region` | нет | `all`, `225`, `149,159,225`; по умолчанию регион из настроек |
| `topic` | нет | `key` тематики из `config/topics.toml` |
| `source` | нет | откуда данные, например `wordstat-manual` |

Пример:

```csv
phrase,count,period,date,topic,source
генератор счетов для ип,820,month,2026-08-01,invoices_acts,wordstat-manual
генератор счетов для ип,910,month,2026-09-01,invoices_acts,wordstat-manual
```

**Тестовые или реальные.** Любой CSV по умолчанию считается **тестовым**. Если в файле
реальные данные (например, вы вручную выписали их из интерфейса Wordstat), укажите
это явно:

```bash
python -m app import-csv мой_файл.csv            # как тестовые данные
python -m app import-csv мой_файл.csv --real     # как реальные
```

Через Telegram: отправьте файл `.csv` боту с подписью `/import` (тестовые) или
`/import real` (реальные). Максимальный размер — 5 МБ.

Повторный импорт того же файла не создаёт дублей: значение за тот же период
просто обновляется.

Если хотите, чтобы файл подхватывался при каждом сканировании, укажите его в
`CSV_IMPORT_PATH`, а `CSV_IS_DEMO` выставьте в `true` или `false`.

## 10. Доступ к Wordstat API

> **Важно (проверено при разработке, октябрь 2026).** Wordstat API переехал в
> **Yandex Search API** (Yandex Cloud / AI Studio). По сообщениям разработчиков
> клиентских библиотек, старый адрес `api.wordstat.yandex.net` с OAuth-токеном
> больше не принимает запросы. Поэтому Search Scout использует новый API:
> `https://searchapi.api.cloud.yandex.net/v2/wordstat/...`, авторизация
> `Authorization: Api-Key <ключ>`, `folderId` в теле запроса.
>
> Из среды разработки официальные страницы yandex.ru и aistudio.yandex.ru были
> недоступны. Поэтому формат запросов собран по открытым клиентам и публикациям,
> а адаптер проверен на поддельном сервере, но **не на настоящем API**. Перед
> подключением сверьтесь с актуальной документацией (ссылки ниже). Если что-то
> отличается, правки нужны только в `app/sources/wordstat.py`.

Что нужно сделать:

1. **Аккаунт Yandex Cloud.** Войдите в <https://console.yandex.cloud> с Яндекс ID.
2. **Платёжный аккаунт.** Создайте его и привяжите карту. Без активного
   платёжного аккаунта Search API, по отзывам, отвечает `403`. Узнайте актуальные
   тарифы и квоты Wordstat на странице тарифов Yandex Search API / AI Studio:
   бот не делает выводов о цене за вас.
3. **Каталог.** Откройте каталог (по умолчанию `default`) и скопируйте его **ID**
   (вида `b1g...`) → это `WORDSTAT_FOLDER_ID`.
4. **Сервисный аккаунт.** В каталоге: «Сервисные аккаунты» → «Создать».
   Назначьте роль **`search-api.webSearch.user`**.
5. **API-ключ.** Откройте сервисный аккаунт → «Создать новый ключ» → «API-ключ».
   Область действия (scope) — **`yc.search-api.execute`**. Скопируйте секрет
   (он показывается один раз) → это `WORDSTAT_API_KEY`.
6. Впишите оба значения в `.env` и проверьте доступ одним запросом:

   ```bash
   python -m app check-wordstat --phrase "генератор счетов"
   ```

   Ответ `OK: получено N фраз` означает, что всё работает. Ошибки разобраны в
   разделе [13](#13-частые-ошибки).
7. При желании узнайте ID регионов: `python -m app regions`.

Документация для сверки:
- описание Wordstat в Search API: <https://aistudio.yandex.ru/docs/en/search-api/concepts/wordstat.html>
- старая документация (для истории): <https://yandex.ru/support2/wordstat/ru/content/api-wordstat>,
  <https://yandex.ru/support2/wordstat/ru/content/api-structure>

**Квоты и расход.** Точные лимиты смотрите в консоли (раздел «Квоты»). В открытых
источниках упоминаются 10 запросов в секунду и около 100 запросов в час, но
официально это не подтверждено. Поэтому настройки по умолчанию осторожные:

- `WORDSTAT_MAX_REQUESTS_PER_SCAN=60` — не больше 60 запросов за сканирование;
- `WORDSTAT_DYNAMICS_PER_SCAN=15` — из них на помесячную динамику;
- `WORDSTAT_RPS=2` и `WORDSTAT_CONCURRENCY=2` — частота и параллельность.

Стартовых фраз больше, чем помещается в одно сканирование. Бот опрашивает те, что
дольше всего ждали, так что полный круг занимает несколько дней. Ошибки 429 и 5xx
повторяются с паузой (учитывается `Retry-After`), а 401 и 403 сразу останавливают
сканирование с понятным сообщением.

**Регион.** Русскоязычная аудитория — это не только Россия. По умолчанию
`WORDSTAT_REGIONS` пуст (все регионы). Можно задать, например, `225,149,159`
(Россия, Беларусь, Казахстан). Метрики хранятся отдельно для каждого набора
регионов, поэтому после смены региона история накапливается заново.

**Google Trends.** Официальный Trends API (анонсирован в июле 2025) на момент
разработки находится в закрытой альфе с доступом по заявкам. Поэтому в MVP его
нет. Неофициальные обходы (например, pytrends) не используются. Когда доступ
появится, адаптер добавляется как ещё один `QuerySource` в `app/sources/`.

## 11. Переход из Demo в Live

1. Получите ключи (раздел 10) и впишите их в `.env`.
2. `SCOUT_MODE=auto` (по умолчанию) включит Live, как только ключи заданы.
   `SCOUT_MODE=live` — строго Live: если ключей нет, бот так и скажет и не
   подменит данные тестовыми. `SCOUT_MODE=demo` — принудительно Demo.
3. Проверьте ключи: `python -m app check-wordstat`.
4. Перезапустите бота и отправьте `/status`: должно быть «Режим: Live».
5. `/scan` — первое реальное сканирование.

Чего ожидать в первые дни: у новых фраз ещё нет истории, поэтому они попадают в
**список наблюдения** с предварительным рейтингом. Бот постепенно запрашивает
помесячную динамику для лучших кандидатов, и те переходят в топ с полным
рейтингом. Пустой топ в первый день — нормально: список не заполняется искусственно.

Демо-данные в Live-режиме не показываются и не удаляются. Удалить их можно,
удалив файл базы, если он больше не нужен.

## 12. Ежедневные отчёты

- Время и часовой пояс: `DAILY_TIME=09:00`, `TIMEZONE=Europe/Moscow`
  (любой пояс из базы IANA: `Asia/Almaty`, `Europe/Minsk`, ...).
- В это время бот делает сканирование и присылает отчёт тем разрешённым
  пользователям, у кого отчёт включён (`/daily_on`, `/daily_off`; по умолчанию
  определяется `DAILY_DEFAULT_ENABLED`).
- **Перезапуски.** Расписание не хранится, а заново строится при старте из `.env`.
  Если бот был выключен в момент отчёта, при следующем запуске в тот же день он
  выполнит пропущенное сканирование и отправит отчёт. Каждая отправка записывается
  в базу, поэтому один и тот же отчёт за дату не придёт дважды.
- Отдельный системный cron не нужен: бот всё равно работает постоянно, чтобы
  отвечать на команды.

## 13. Частые ошибки

| Симптом | Причина и решение |
|---|---|
| `TELEGRAM_BOT_TOKEN не задан` | Нет `.env` или токен пуст. Скопируйте `.env.example` в `.env` |
| Бот отвечает «Это приватный бот» | Ваш ID не в `ALLOWED_USER_IDS`. Впишите ID из ответа и перезапустите |
| `Бот уже запущен (занята блокировка ...)` | Запущена вторая копия на этом компьютере. Закройте её |
| В логе `TelegramConflictError` / `Conflict: terminated by other getUpdates` | Тот же токен используется на другом компьютере или сервере. Остановите другую копию |
| `Ошибка в настройках (.env)` | Неверный формат значения: время `ЧЧ:ММ`, ID — числа через запятую |
| `Live-режим недоступен` | `SCOUT_MODE=live`, но нет `WORDSTAT_API_KEY` или `WORDSTAT_FOLDER_ID` |
| `HTTP 401/403` от Wordstat | Неверный ключ, не та роль у сервисного аккаунта, неверный ID каталога, не привязан платёжный аккаунт |
| `HTTP 429` | Превышена квота. Уменьшите `WORDSTAT_MAX_REQUESTS_PER_SCAN` или `WORDSTAT_RPS` |
| `HTTP 400` на динамике | Бот сам переключится на 12 месяцев. Если ошибка повторяется, сверьте формат с документацией |
| `py`/`python` не найден (Windows) | Python не добавлен в PATH: переустановите с галочкой «Add to PATH» |
| `ModuleNotFoundError` | Не активировано окружение `.venv` или не установлены зависимости |
| Топ пустой | Нет фраз с историей выше порога. Смотрите `/watchlist`, подождите следующих сканирований |
| Отчёт не пришёл | `/status` покажет время следующего запуска и ошибку последнего; проверьте `/daily_on` |

Логи выводятся в консоль. Токены и ключи в них маскируются (`***`). Подробнее —
`LOG_LEVEL=DEBUG`.

## 14. Размещение на VPS

Боту не нужен публичный IP и открытые порты: он сам опрашивает Telegram (polling).

1. Сервер с Ubuntu 22.04+ и Python 3.12+. Создайте отдельного пользователя:
   `sudo adduser --disabled-password scout`.
2. Скопируйте проект (`git clone` или `scp`) в `/home/scout/search-scout`.
3. Создайте окружение и поставьте зависимости: `python3 -m venv .venv && .venv/bin/pip install -r requirements.txt`.
4. Создайте `.env` и закройте к нему доступ: `chmod 600 .env`.
5. **Остановите бота на своём компьютере**: один токен — одна работающая копия.
6. Создайте службу systemd `/etc/systemd/system/search-scout.service`:

   ```ini
   [Unit]
   Description=Search Scout Telegram bot
   After=network-online.target
   Wants=network-online.target

   [Service]
   User=scout
   WorkingDirectory=/home/scout/search-scout
   ExecStart=/home/scout/search-scout/.venv/bin/python -m app
   Restart=on-failure
   RestartSec=10
   NoNewPrivileges=true
   PrivateTmp=true

   [Install]
   WantedBy=multi-user.target
   ```

   ```bash
   sudo systemctl daemon-reload
   sudo systemctl enable --now search-scout
   journalctl -u search-scout -f     # логи
   ```
7. **Резервные копии.** Копируйте файл `data/search_scout.sqlite3`, например раз в
   день по cron: `sqlite3 data/search_scout.sqlite3 ".backup data/backup.sqlite3"`.
8. **Обновление:** `git pull`, затем `.venv/bin/pip install -r requirements.txt` и
   `sudo systemctl restart search-scout`. Миграции базы применятся сами.
9. Безопасность: вход на сервер по SSH-ключу, обновления системы
   (`unattended-upgrades`), закрытый файрвол (`ufw allow OpenSSH && ufw enable`).

## Алгоритм оценки

1. **Сбор.** По каждой стартовой фразе источник возвращает её частотность и похожие
   запросы. Стартовые фразы — это `seeds` из `topics.toml` плюс сочетания
   `core × modifiers` («генератор счетов» + «онлайн»). Лучшие короткие фразы из
   топа становятся новыми стартовыми фразами.
2. **Нормализация.** Нижний регистр, ё→е, без операторов Wordstat, пунктуации и
   лишних пробелов. Исходная формулировка сохраняется. Точные дубликаты
   объединяются. Близкие формулировки («конвертер pdf» / «конвертеры pdf»)
   группируются по основам слов **с сохранением порядка**, поэтому «из pdf в word»
   и «из word в pdf» не смешиваются. В отчёте показывается лучшая фраза группы.
3. **Отбор по тематикам.** Фраза должна содержать хотя бы один `stem` тематики и не
   содержать стоп-слов (`[filters]`).
4. **Динамика** (`app/services/trend.py`). Используются только полные месяцы:
   среднее за последние 3 месяца против предыдущих 3 (при истории 4–5 месяцев —
   2 против 2). Есть защита от деления на ноль и порог объёма. Если вырос только
   последний месяц — это всплеск, балл динамики ограничивается 50. Если изменение
   повторяет прошлогодний сезон (нужно ≥ 13 месяцев), в балл идёт сравнение год к
   году. Без истории — статус «недостаточно истории».
5. **Намерение** (`app/services/intent.py`) — правила по словам: транзакционный,
   сравнение/альтернатива, инструмент, проблема, информационный. Бизнес-аудитория
   повышает балл, «бесплатно» и «скачать» понижают. Отдельно считается
   выраженность проблемы («не работает», «вручную», «массово», «чем заменить» …).
6. **Рейтинг 0–100.** Каждый компонент сначала приводится к 0–100, затем
   взвешивается: динамика 35%, намерение 30%, проблема 20%, новизна 15%. Если
   динамики нет, итог считается по доступным компонентам с перенормировкой весов
   и помечается **предварительным**; `completeness` показывает долю веса с
   реальными данными. Уверенность: высокая (≥ 12 месяцев истории без всплеска),
   средняя, низкая (нет динамики).
7. **Отбор.** `top` — полный рейтинг не ниже `TOP_MIN_SCORE`. `watch` — новые фразы
   без истории с заметным намерением и разовые всплески. `rejected` — падающий
   спрос, малый объём, низкий рейтинг (они видны в `/export`).

Для каждой оценки в базе хранятся итог, компоненты, причины, использованные данные,
уверенность и дата последнего наблюдения.

## Что проверено, а что нет

Проверено автоматически при разработке:
- 101 автотест (`pytest`) на Python 3.12 и 3.13, `ruff check` и `ruff format` — без замечаний;
- сценарий первого запуска в Demo-режиме: создание базы, импорт демо-CSV,
  сканирование, отчёт, экспорт;
- запуск настоящего бота (aiogram) против **локального поддельного** Telegram
  Bot API: команды, отказ постороннему пользователю, восстановление пропущенного
  ежедневного отчёта, корректная остановка;
- Live-сканирование против **локального поддельного** Wordstat-сервера: формат
  запросов, повтор после 429, динамика, расширение сидов.

Требует ваших действий и токенов (не проверялось):
- работа с настоящим Telegram (нужен токен от @BotFather);
- работа с настоящим Wordstat API: ключи, роли, биллинг, квоты, точный формат
  ответов. Проверка — `python -m app check-wordstat` и `pytest -m live`;
- запуск на Windows (код учитывает Windows: блокировка файла, кодировки CSV,
  пакет `tzdata`, но на Windows он не запускался).

## Что улучшить дальше

1. Подключить и проверить настоящий Wordstat. Затем подстроить пороги
   (`TOP_MIN_SCORE`, `MIN_MONTHLY_VOLUME`) под реальные объёмы.
